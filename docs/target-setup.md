# Сканирование другого ПК

## На целевом ПК

1. Откройте 64-разрядную Windows PowerShell 5.1 от администратора и перейдите в папку комплекта. На 32-разрядной Windows используйте штатную Windows PowerShell 5.1. Скриптам нужны все файлы из `deploy`. Проверьте, что служба **«Сервер» (LanmanServer)** запущена.
2. Подготовьте учётную запись. В рабочей группе нужна локальная учётка целевого ПК с паролем и частный профиль сети. В домене нужен уже присоединённый к домену ПК с доменным профилем сети, группа безопасности AD и пользователь в этой группе.
3. Для первого прогона импортируйте открытый образец в **«Личное» локального компьютера**, чтобы появилось хранилище `MY` с сертификатом:

   ```powershell
   Import-Certificate -FilePath .\app\samples\organizer-1.cer -CertStoreLocation Cert:\LocalMachine\My
   ```

4. Выберите одну команду для своей сети. `-WhatIf` покажет план изменений:

   ```powershell
   # Рабочая группа
   .\deploy\Prepare-CertScopeWorkgroup.ps1 -WhatIf

   # Домен
   .\deploy\Prepare-CertScopeDomain.ps1 -WhatIf
   ```

   Введите локального пользователя (`ИМЯ-ПК\certreader`) или доменную группу (`ДОМЕН\CertScope-Readers`) и частный IPv4 **ПК-сканера**. На запрос хранилищ нажмите Enter для `HKLM\SOFTWARE\Microsoft\SystemCertificates\MY`. Если нужны другие существующие хранилища, введите их полные пути через `;`.
5. Повторите выбранную команду без `-WhatIf` с теми же ответами. Скрипт запускает **Remote Registry**, переводит службу в режим автоматического запуска и добавляет правило для входящего TCP 445 с указанного IP на нужном профиле. Он выдаёт чтение выбранных хранилищ и шлюза `winreg`. Через этот шлюз учётка также сможет читать ключи, на которые у неё уже есть права.

## На ПК-сканере

Откройте в CertScope вкладку **«Настройки»** и заполните поля для прогона из примера:

| Поле | Рабочая группа | Домен |
| --- | --- | --- |
| Компьютеры | Имя или IPv4 целевого ПК | DNS-имя целевого ПК |
| Домен | Имя целевого ПК | Короткое имя домена AD, например `CERTSCOPE` |
| Пользователь | Имя локальной учётки, например `certreader` | Имя пользователя из группы чтения |
| Пароль | Пароль локальной учётки целевого ПК | Пароль доменного пользователя |

Снимите все флажки в **«Области сбора»**. Оставьте **«Каталоги»** и **«Выбранные SID»** пустыми. В **«Дополнительные ветки»** вставьте `HKLM\SOFTWARE\Microsoft\SystemCertificates\MY` или перечислите согласованные пути по одному в строке. Для 64-разрядной цели оставьте включённым представление **«64 бита»**.

Нажмите **«Сканировать»**, затем откройте **«Сертификаты»** для проверки образца и **«Охват и ошибки»** для проверки статуса ветки. Пароль Windows вводится в CertScope заново перед каждым запуском. При статусе **«Недоступен»** проверьте TCP 445 со сканера командой `Test-NetConnection 'ИМЯ-ПК' -Port 445`. При **«Отказе в доступе»** проверьте пароль Windows, права сетевого входа и чтение указанной ветки.

## Откат и управление через GPO

На целевом ПК запустите тот же скрипт с `-Undo` вместо `-WhatIf` и введите прежнюю учётку или группу и IPv4 сканера. Для восстановления нужна сохранённая на цели копия `%ProgramData%\CertScopeRegistryAccess\target-setup.json`.

Если в домене службой и брандмауэром уже управляет GPO, для разрешений реестра используйте `deploy/Grant-CertScopeRegistryRead.ps1` с `-ReaderGroup` и `-RegistryBranches`. Параметр `-GrantWinreg` добавляет чтение шлюза при необходимости. После проверки на одном ПК этому скрипту можно передать параметры в сценарии запуска компьютера через GPO.
